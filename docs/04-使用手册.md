# 04-使用手册

> 本手册面向两种读者：**人类用户**（如何安装、配置、调试）与 **agent**（如何调用这套 MCP 工具完成"生成视频笔记"）。快速上手见 [README](../README.md)，本手册是详细参考。

## 前提

- **uv**（Python 包管理器，必需）：`curl -LsSf https://astral.sh/uv/install.sh | sh` 或 `brew install uv`（没有 uv 走[安装方式四](#安装)，脚本内置 pip 兜底）
- **Python ≥ 3.11，<3.14**（推荐 3.12）
- **FFmpeg**：`brew install ffmpeg`（Linux：`apt install ffmpeg`）
- **LLM 供应商 API Key**（见[配置](#配置装完必做)）
- **本地转写**：本地 whisper 需先 `bilinote-mcp transcriber download <size>`，或改用云端 `groq` / `bcut`
- **GPU 加速（可选）**：NVIDIA/Linux 想用 CUDA → 装工具时 `--with torch`（whisper 自动检测 GPU，默认 CPU）；macOS Apple Silicon → `--with mlx-whisper` + `bilinote-mcp transcriber set mlx-whisper`
- **CLI 命令简写**：正文里的 `bilinote-mcp ...` 等价于：
  - 有 uv：`uvx --from git+https://github.com/HuangYincan/BiliNote-MCP bilinote-mcp ...`（`--from` 必须带 `git+` 前缀）
  - 源码（方式四）：`<仓库路径>/.venv/bin/bilinote-mcp ...`

## 配置（装完必做）

> 所有方式共用同一数据目录（`~/.local/share/bilinote-mcp/`），配好即会话内生效。

### 交互向导 `setup`（推荐，随时可反复进入修改）

```bash
bilinote-mcp setup
```

**方向键选择 + 高亮**、**左键返回上一级**、每步自动清屏；**不是一次性程序**，随时重跑即可改配置：① LLM 供应商（填/改 key、新增中转站、**检测连接 / 列模型 / 设默认模型**）→ ② 转写引擎 + 模型尺寸（未下载会提示下载）→ ③ 平台 Cookie（下拉选择）/ 默认笔记位置（持久化）/ **视频理解默认**（开/关 + 帧间隔秒数，持久化）/ **评论/弹幕整合默认**（开/关 + 评论条数，持久化，需 B 站 SESSDATA）/ **笔记默认**（`default_style` 默认 detailed、`default_screenshot` 默认关、`agent_direct` 默认关，持久化）—— **全自动模式**套用这些默认（会先列出完整参数清单给用户确认）。

### LLM 供应商（key 走 CLI，对话外）

内置供应商（openai / deepseek / qwen / groq / ollama…）在空库时已自动预置，id 固定、base_url 正确，**只需填 key**：

```bash
# 终端（key 不进对话）
bilinote-mcp providers list                                  # 看内置供应商，key 为空
bilinote-mcp providers set deepseek --api-key 'sk-你的key'     # 填 key（掩码回显）
bilinote-mcp providers test deepseek                          # 检测连接 + 列出可用模型
bilinote-mcp providers test deepseek --default deepseek-chat   # 检测并设为默认模型
```

**检测连接 / 设默认**：`setup` 向导里选中某供应商会进入「管理」子菜单（✏ 编辑 key/base_url / 🔌 检测连接 → 列出模型 → 设默认 / ← 返回）。检测用 OpenAI 兼容 `GET /v1/models`（一次验证 key/base_url 并拿到模型列表）；`/v1/models` 不可用（部分中转站/自建网关）时降级为「最小对话请求」chat 探测。默认模型持久化在 `config/app_config.json`（`default_model:{provider_id}`）—— `generate_note` **未指定 `model_name` 时优先用配置的默认模型**，再退 DB 第一条。

```text
# agent 侧（只做非敏感操作）
list_providers()                            # deepseek key=已填（掩码，看不到明文）
list_models("deepseek")                     # 实时拉 /v1/models；失败回退本地库
add_model(provider_id="deepseek", model_name="deepseek-chat")   # 实时拉不到时手动加
```

**中转站 / 自建网关**（非内置）：终端新增

```bash
bilinote-mcp providers add --name 我的中转站 --api-key 'sk-中转站发的key' --base-url 'https://relay.example.com/v1'
bilinote-mcp providers list                                    # 记下新供应商 id
```

**没有 LLM key？** 本地装 [Ollama](https://ollama.com) 并 `ollama pull llama3`，内置 `ollama` 供应商**无需 key**，`list_models("ollama")` 有模型即可用；或注册 Groq/DeepSeek 免费额度后 `providers set` 填 key。

### 转写引擎

**终端直接切换（推荐，非交互）：**

```bash
bilinote-mcp transcriber list                          # 查看当前引擎与就绪状态
bilinote-mcp transcriber set fast-whisper --size small  # 切本地 whisper
bilinote-mcp transcriber download small                  # 下载 fast-whisper 模型
bilinote-mcp transcriber download small --engine mlx-whisper  # 下载 mlx-whisper（macOS）

# B 站：优先用平台字幕（含 AI 字幕）跳过语音识别；AI 字幕需登录态
bilinote-mcp login bilibili     # 扫码登录，自动获取并保存 SESSDATA
bilinote-mcp transcriber set groq                        # 切云端
```

**引擎**：`fast-whisper`（本地）/ `groq` / `bcut` / `kuaishou`（云端）/ `mlx-whisper`（**仅 macOS Apple Silicon**，GPU 加速）。
**whisper 尺寸**：`tiny` / `base` / `small` / `medium` / `large-v3` / `large-v3-turbo`（turbo 更快、精度略低）。
**设备**：whisper 自动检测 CUDA（有 torch+CUDA 用 GPU，否则 CPU）；macOS 用 `mlx-whisper` 走 Apple Silicon GPU。CLI `download` 用 CPU 只是下载权重、不推理。

**或 agent 侧用工具：**

```text
get_transcriber_config()           # 当前：fast-whisper / tiny

# 本地离线转写（推荐，免费）：切引擎 + 下载对应尺寸模型
set_transcriber("fast-whisper", "small")
download_transcriber_model("small")            # 后台下载；list_transcriber_models 看到 state=done 即就绪

# 云端转写（快、省资源，需 key）：先在独立终端填 key，再直接切
#   独立终端：bilinote-mcp providers set groq --api-key 'gsk-你的key'
set_transcriber("groq")
get_transcriber_config()           # ready=true 即就绪
```

> whisper 模型尺寸（约）：tiny 75MB / base 145MB / small 460MB / medium 1.5GB / large-v3 3GB。够用选 small 及以下，追求精度再上 medium+。
> macOS Apple Silicon 可用 MLX Whisper（`set_transcriber("mlx-whisper", "small")`），需安装时带 `--with mlx-whisper`。

### 平台 Cookie（B 站等）

部分平台需登录 Cookie 才能下载高清/完整内容：

```text
set_downloader_cookie(platform="bilibili", cookie="SESSDATA=...")
```

|------|----------|----------|
| `generate_note` | `video_url`（必填）、`platform`（可省略自动识别）、`quality`(fast/medium/slow)、`model_name`、`provider_id`、`format`(["toc","link","screenshot","summary"])、`style`、`extras`（自定义 prompt 后缀，自定义风格用）、`screenshot`、`link`、`video_understanding`、`video_interval`、`grid_size`、`include_comments`、`comments_limit`（评论/弹幕整合，需 SESSDATA）、`notes_dir`（便携笔记位置，可选） | `{task_id}` |
| `prepare_note_material` | `video_url`（必填）、`platform`、`video_understanding`、`video_interval`、`grid_size`、`include_comments`、`comments_limit` | **只准备素材、不调用配置 LLM**；`{task_id}`，`get_task_status` 轮询到 SUCCESS 时 `result` = 素材包：`{kind:"material", title, transcript:{language, full_text, segments}, frames:[file://...jpg], comments_danmaku, video_path, audio_path}` —— 供 **AGENT 直接生成**（agent_direct） |
| `get_task_status` | `task_id` | `{status, message, result?}`，SUCCESS 时 `result.markdown`（或素材包 `result`，见 `prepare_note_material`） |
| `wait_for_note` | `task_id`、`timeout`(秒，默认120) | **阻塞**轮询到 SUCCESS/FAILED/CANCELLED，返回 Markdown（多任务并行时勿用，会卡住当前轮次） |
| `cancel_note` | `task_id` | 取消进行中/排队的任务（协作式，下一阶段边界生效） |
| `list_providers` | — | 供应商列表（id/name/type/enabled/key 掩码） |
| `add_provider` / `update_provider` | `name`、`api_key`、`base_url`、`type` / `provider_id` + 非敏感字段 | 新供应商 id / 更新结果（**填 key 建议走 CLI**） |
| `list_models` | `provider_id` | 该供应商可用模型（实时 /v1/models，回退本地 DB） |
| `add_model` | `provider_id`、`model_name` | 手动把模型名加入供应商（接口不可用时） |
| `get_transcriber_config` | — | 当前转写引擎与模型尺寸 |
| `set_transcriber` | `transcriber_type`(fast-whisper/groq/bcut/mlx…)、`whisper_model_size` | 新配置 |
| `list_transcriber_models` | — | 本地已下载的 whisper 模型 |
| `download_transcriber_model` | `model_size`、`transcriber_type` | 触发下载（后台） |
| `health_check` | — | ffmpeg / db / whisper 状态 |
| `validate_url` | `url` | 识别到的平台 |
| `set_downloader_cookie` | `platform`、`cookie` | — |
| `fetch_comments` | `video_url`、`limit`(默认 20) | B 站视频评论区内容（需 SESSDATA） |
| `fetch_danmaku` | `video_url` | B 站视频弹幕（需 SESSDATA） |
| `get_task_files` | `task_id` | 该任务在磁盘上的文件/目录（`{task_id, manifest_paths, existing}`），清理前先查 |
| `cleanup_note` | `task_id`、`include_note`(默认 False) | 删该任务中间产物，默认保留最终笔记；`include_note=True` 连笔记+manifest 一起删 |
| `cleanup_all` | `include_config`(默认 False)、`include_models`(默认 False) | 全局清空 note_results/static/logs（恢复出厂）；`include_config=True`/`include_models=True` 才清 config/models |

## 视频理解（画面切片）

把视频画面按时间间隔切片发给**多模态 LLM** 做「看画面」的理解（与 BiliNote 前端同一套 VideoReader）：

```text
generate_note(video_url=..., provider_id="qwen", model_name="qwen-vl-plus",
              video_understanding=True, video_interval=6, grid_size=[3, 3])
```

- **流程**：下载视频 → 每 `video_interval` 秒抽一帧 → 按 `grid_size` 拼成网格图 → 转 base64 data URI → 以 OpenAI 多模态 `image_url` 数组发给 LLM（图片内嵌在请求里，无需外网可访问地址）。
- **必须用多模态模型**：qwen-vl / gpt-4o 等；deepseek-chat 等纯文本模型不支持，会退回纯文本。
- `video_interval` 缺省 6 秒；`grid_size` 缺省自动 `[3, 3]`（`screenshot` 模式为 `[2, 2]`）。
- **默认值可在 setup ③ 配置**（默认关 / 6s）：agent 未显式传 `video_understanding` / `video_interval` 时自动套用；**手动模式下 SKILL 仍要求先问用户**本次是否启用 + 间隔，只有用户说「你定/用默认」才用默认值；**全自动模式**套默认（先列出参数清单待确认）。
- 注意：视频理解会**下载整个视频**并抽帧，比纯音频转写慢且占磁盘；`video_interval` 越大越省。
- 想要 markdown 里按 `*Screenshot-mm:ss` 标记插**单张**截图，用 `format=["screenshot"]`（区别于整片帧网格）。

## 整合弹幕+评论区观点

把 B 站**弹幕**和**评论区**的高频观点也整理进笔记（哪些弹幕刷屏、评论区在聊什么），`generate_note` 加：

```text
generate_note(video_url=..., ..., include_comments=True, comments_limit=20)
```

- 整合弹幕+评论区观点，让笔记不仅来自音轨，还能反映观众讨论；
- **笔记会新增一节「观众观点」**：总结弹幕刷屏/评论区反复出现的观点、补充、纠错（引用实际内容，不捏造）；无可总结时写「（无）」；
- `comments_limit` 控制抓取的评论条数（默认 20）；
- **需 B 站 SESSDATA**（登录态）：没配则评论拿不到 —— 先 `bilinote-mcp login bilibili` 扫码（或 `set_downloader_cookie(platform="bilibili", cookie="SESSDATA=...")`）；
- **抓取失败不阻断任务**：拿不到评论/弹幕时笔记照常生成，跳过该部分即可；
- 只想单独拉数据看，用 `fetch_comments(video_url, limit=20)` / `fetch_danmaku(video_url)` 两个工具；
- **默认值可在 setup ③ 配置**（默认关 / 20条）：agent 未显式传 `include_comments` / `comments_limit` 时自动套用；**手动模式下 SKILL 仍要求先问用户**本次是否整合，只有用户说「你定/用默认」才用默认值；**全自动模式**套默认（先列出参数清单待确认）。

## 图片插入（便携笔记 Assets）

`format=["screenshot"]`（配合 `screenshot=True` 让 LLM 生成 `*Screenshot-[mm:ss]` 标记）会把标记替换成截图，并产出**便携笔记**：

```text
generate_note(video_url=..., ..., screenshot=True, format=["screenshot"])
```

- 结果：`note_dir/note.md` + `note_dir/Assets/*.jpg`，markdown 用**相对引用** `![...](Assets/xxx.jpg)`，整个文件夹可整体搬迁；
- 任务结果里 `result.note_dir` 指向该目录（agent 据此告诉你笔记位置、读图以它为基准）；
- **保存位置**优先级：
  1. `generate_note(..., notes_dir="/你/指定/的目录")`；
  2. 环境变量 `BILINOTE_NOTES_DIR`；
  3. 默认 `note_results/{task_id}/`。
- **指定 `notes_dir` 时每篇笔记一个文件夹**：`<notes_dir>/<笔记标题>/note.md`（标题取 LLM 生成的笔记 H1，回退视频标题；同名冲突自动加短 task_id 后缀）—— 多篇互不覆盖，且即使不插图片也会写文件。
- 与视频理解搭配更自然（`video_understanding=True` 时画面分析 + 截图都基于同一次视频下载）。

## 清理与存储

任务产生的文件（下载的视频/音频、转写、截图、`dl_{task_id}/` 下载目录等）会堆积占存储，agent 可自助清理：

- **先查后清**：`get_task_files(task_id)` —— 返回 `{task_id, manifest_paths, existing}`。
  - `manifest_paths`：`note_results/{task_id}.manifest.json` 里记录的路径（流水线在生成时尽力而为写入，失败不阻断）；
  - `existing`：manifest 记录 + `{task_id}*` 前缀扫描后**真实存在**的文件/目录（含 `dl_{task_id}/`、便携笔记目录、`{task_id}/frames` 等）。
- **按任务清理**：`cleanup_note(task_id, include_note=False)` —— 删该任务中间产物（manifest 记录路径 + `note_results/{task_id}*` + `dl_{task_id}/` + `{task_id}/Assets` 等）。
  - `include_note=False`（默认）：**保留最终笔记** `note.md` / `note_dir`；
  - `include_note=True`：连最终笔记 + manifest 一起删。
- **全局清理（恢复出厂）**：`cleanup_all(include_config=False, include_models=False)` —— 清空 `note_results/*`、`static/screenshots/*`、`logs/*`。
  - **默认保留** `config/`（LLM key / cookie / 转写设置）与 `models/`（已下载模型可复用、重下成本高）；
  - `include_config=True` 连 `config/` 一起清；`include_models=True` 连 `models/` 一起清；
  - 数据库记录（`bili_note.db`）不动。
- **安全**：只删 manifest 记录 / 明确前缀模式（`note_results/{task_id}`、`dl_{task_id}`、`{task_id}/`）的文件，删除前 `resolve()` 校验在 `NOTE_OUTPUT_DIR` / `DATA_DIR` 内（防路径穿越）；删除失败逐条跳过并返回统计（`deleted/missing/errors`）。

## Agent 工作流

一次典型的"给视频做笔记"任务，agent 应按顺序调用：

1. `health_check` —— 确认 ffmpeg/db 就绪；
2. `list_providers` —— 确认有供应商且 key=已填（**没有就让用户用 CLI 配，agent 不碰 key**）；
3. `generate_note(video_url=..., provider_id=..., model_name=...)` —— 拿 task_id；
4. `get_task_status(task_id)` **轻量快照轮询**，等到 `SUCCESS`/`FAILED`/`CANCELLED`（**任务一次只发一个**，server 有进行中任务会拒绝新提交；不要并行塞多个 `generate_note`；`wait_for_note` 是阻塞调用）；
5. SUCCESS 后拿到 `result.markdown` —— **阅读该 Markdown 并用它回答用户的所有问题**（不要发明笔记里没有的内容）；
6. 若用户要的是"视频里某个细节"，可在 Markdown 之外再 `get_task_status` 拿 `result.transcript`（完整转写）辅助定位；
7. **问用户是否要根据笔记 + 提取的字幕做后续优化**（补齐遗漏、修正与字幕不一致处、增强结构）—— agent 读 `result.markdown` + `result.transcript` 自己精修（转写过长时按章节精修并如实告知限制）。

示例对话：

> 用户：帮我给这个视频做个笔记 https://www.youtube.com/watch?v=xxxx
>
> agent：先问「全自动/手动」；`validate_url` → youtube；`list_providers` 确认供应商 key=已填；按模式确认参数 → `generate_note` → 轮询 → SUCCESS；展示 Markdown 并总结要点。

## 全自动 / 手动模式 + AGENT 直接生成

任务开始时 agent **会先问用户「全自动」还是「手动」**（SKILL 强制规则第 0 条）：

- **全自动**：用 setup ③ 的默认解析出**完整参数清单**（生成方式/LLM 模型（或选 AGENT 直接生成）/ `default_style`（默认 detailed）/ 视频理解默认 / 评论默认 / 截图默认 / **生成后是否后续优化**），**一次性列给用户确认**、不逐个问；用户要改某项再以提问方式改，确认后 `generate_note` 不传 style / screenshot / video_understanding / include_comments / agent_direct 即套默认。「AGENT 直接生成」在选 LLM 模型阶段提供（默认用配置 LLM）。适合「按已配好的默认跑」的日常任务。
- **手动**：逐个确认参数（LLM 模型、笔记风格、视频理解、评论/弹幕、截图、是否 AGENT 直接生成），确认完再生成。适合想精细控制每次输出时。

**AGENT 直接生成（`agent_direct`）**：在**选 LLM 模型阶段**提供选项 —— 手动模式问「用哪个模型，还是 AGENT 直接生成」；全自动模式默认用配置 LLM，可在参数清单里改选。开启后**不走配置的 LLM**，由 agent 自己写笔记：

1. `prepare_note_material(video_url, video_understanding?, video_interval?, include_comments?, comments_limit?)` → `task_id`；
2. `get_task_status(task_id)` 轮询到 `SUCCESS` → 拿到**素材包**：`result.transcript.full_text`（完整转写）、`result.frames`（`file://` 抽帧图，多模态模型下用 Read 看图）、`result.comments_danmaku`（评论/弹幕）；
3. agent 读转写 / 看图 → **自己写 Markdown**（问风格，默认 detailed；素材包里有 `comments_danmaku` 时笔记新增一节「观众观点」总结观众观点）→ 呈现。

转写可能很长（如 2h 视频超上下文）—— agent **按章节分段精修**或让用户指定重点。其余流程（health_check / validate_url / 轮询 / 后续优化）与常规一致。

## Skill 使用

仓库自带 Claude Code Skill（`skills/bilinote/SKILL.md`），它教 agent 用上面的流程**一句话完成「视频 → 笔记」**（触发词：「生成视频笔记」「帮这个视频做笔记」「从 XX 链接做笔记」）。通过插件 marketplace 安装（同时装好 Skill 与 MCP server）：

```bash
claude plugin marketplace add HuangYincan/BiliNote-MCP
claude plugin install bilinote@bilinote
```

装完重启会话（或 `/reload-plugins`），之后在 Claude Code 里说「帮我给这个视频做笔记」+ 链接即可触发。

> Skill 更新（三步各有用）：`claude plugin marketplace update bilinote`（拉最新 commit）→ `claude plugin disable bilinote@bilinote` → `claude plugin install bilinote@bilinote`（`install` 单独会被「已安装」跳过，必须先 `disable`；不 `marketplace update` 则拉的还是旧克隆）。

## 开发版（dev 分支尝鲜）

`dev` 分支有未发布的新功能（尝鲜/测试用）。已装 main 稳定版后切 dev：

**MCP 工具指 dev**（覆盖插件的 main MCP）：

```bash
claude mcp remove bilinote                                 # 如果先前在 main：先移除插件默认的 main MCP，再覆盖成 dev（同名 add 才能生效）
claude mcp add --scope user bilinote -- uvx --from git+https://github.com/HuangYincan/BiliNote-MCP@dev bilinote-mcp
```

**SKILL 也指 dev**（marketplace 指到 dev 分支）：

```bash
claude plugin marketplace add HuangYincan/BiliNote-MCP@dev
claude plugin disable bilinote@bilinote
claude plugin install bilinote@bilinote
```

重启会话（或 `/reload-plugins`）生效。

> **已经 pin 到 dev 后，代码更新了**：只需 `claude plugin marketplace update bilinote`（拉到 dev 最新 commit，`ref: dev` 会保留），再 `disable` + `install`；不用重新 `add @dev`。只有 marketplace 被切回 main 时才需要再 `add ...@dev`。

**切回 main（稳定版）**：

```bash
claude mcp remove bilinote                                   # MCP 恢复插件默认（main）
claude plugin marketplace add HuangYincan/BiliNote-MCP       # marketplace 回 main
claude plugin disable bilinote@bilinote
claude plugin install bilinote@bilinote
# /reload-plugins
```

**CLI 用 dev**：`uvx --from git+https://github.com/HuangYincan/BiliNote-MCP@dev bilinote-mcp setup`（PATH 上的 `bilinote-mcp` 若是 main 固定版）。

> **注意**：
> - dev 与 main **共用数据目录** `~/.local/share/bilinote-mcp/`：LLM key / SESSDATA / 转写配置自动带过来，**不用重配**；共用同一 SQLite，别两个同时跑任务。
> - marketplace 指 dev 会**替换**生产 marketplace（不并存），测完切回 main。
> - `git+...@dev` 是 uv/uvx 的分支 ref 语法；默认安装（无 ref）拉 **main**。
> - marketplace 指 dev 只换 **SKILL**；MCP 工具需手动 `@dev` 覆盖（marketplace.json 的 uvx 无 ref 仍 main）。

## 故障排查

| 现象 | 原因 / 解决 |
|------|-------------|
| `health_check` 显示 `ffmpeg: missing` | 安装 FFmpeg（`brew install ffmpeg`）后重启 |
| `list_providers` 里 key 为空 | 在独立终端 `bilinote-mcp providers set <id> --api-key '...'` |
| 提示"不支持的转写器" | `get_transcriber_config` 查看，`set_transcriber` 改回 `fast-whisper` |
| whisper 转写时报模型未下载 | `download_transcriber_model(model_size="small")` 后重试，或切 `groq` |
| `generate_note` 报"供应商不存在" | 先用 CLI 配好供应商与 key，再 `list_models` / `add_model` 确认模型，把正确 `provider_id`/`model_name` 传入 |
| 首次转写卡在 `INITIALIZING` | 正在下载 whisper 模型，耐心等；模型大可改用云端转写 |
| `validate_url` 返回不支持 | 该链接平台不在支持列表（youtube/bilibili/tiktok/kuaishou/douyin/local） |
| 任务长时间卡住 | `get_task_status` 看 message；可能视频很长或模型下载中，耐心等待或换小模型 |
| 中文乱码/内容差 | 检查所选模型能力；`style` 会影响输出格式 |
