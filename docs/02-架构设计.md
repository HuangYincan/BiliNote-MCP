# 02-架构设计

## 总体数据流

```
视频链接 (URL / 本地文件)
   │
   ▼  ① 下载（yt-dlp 适配器，按平台选择）
音频 / 视频文件 + 元信息
   │
   ▼  ② 字幕优先，无则转写（faster-whisper 本地 / groq / bcut 云端）
TranscriptResult (语言 + 分段全文)
   │
   ▼  ③ LLM 总结（GPT 工厂，按 provider_id 选择模型）
Markdown 文本（含可选截图/链接标记）
   │
   ▼  ④ 后处理（截图生成、链接替换、源链接前缀）
   │
   ▼  ⑤ 落盘：note_results/{task_id}.status.json + {task_id}.json
```

agent 的调用时序：`generate_note`（拿到 task_id）→ 轮询 `get_task_status` / `wait_for_note`（拿到 Markdown）→ **由 agent 自己阅读 Markdown 回答问题**。

## 运行时约定（`bilinote_mcp/config.py` 在 import `app.*` 之前设置）

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `BILINOTE_DATA_DIR` | `<仓库>/data` | 运行时数据根目录 |
| `DATABASE_URL` | `sqlite:///<data>/bili_note.db` | SQLite 路径（engine.py 已读该变量） |
| `NOTE_OUTPUT_DIR` | `<data>/note_results` | 任务状态文件与结果 JSON |
| `IMAGE_OUTPUT_DIR` | `<data>/static/screenshots` | 截图输出 |
| `IMAGE_BASE_URL` | `file://<data>/static/screenshots` | Markdown 中图片 URL 前缀（让 agent 可直接读取） |
| `TRANSCRIBER_TYPE` | `fast-whisper` | 转写引擎，可被 `set_transcriber` 覆盖 |

> 复用已有 BiliNote 数据库：将 `DATABASE_URL` 指向旧 `bili_note.db` 即可继承已配置的 LLM 供应商，无需重新配置。

## 异步任务与状态文件

- `generate_note` 是**异步**的：立即返回 `task_id`，后台线程执行 `NoteGenerator.generate()`。
- 执行过程与上游完全一致地写状态文件：`note_results/{task_id}.status.json`（内容 `{status, message?}`，枚举见 `app/enmus/task_status_enums.py`：PENDING → PARSING → DOWNLOADING → TRANSCRIBING → SUMMARIZING → FORMATTING → SAVING → SUCCESS/FAILED）。
- 成功后写 `note_results/{task_id}.json`（含 `markdown`、`transcript`、`audio_meta`）。
- `get_task_status` 读取这两个文件并返回；`wait_for_note` 是带超时的轮询封装。

## 关键设计决策

1. **无 RAG**：agent 拿到 Markdown 后自行推理，省去 ChromaDB + embedding 模型（数百 MB）与向量库维护。
2. **本地 + 云端转写并存**：默认 `fast-whisper`（离线、免费），可切 `groq`/`bcut`（快、省资源、需 key）。
3. **后台线程执行**：MCP server 是常驻 stdio 进程，用线程池跑长任务，避免阻塞工具调用。
4. **DB 复用**：SQLite schema 与上游一致，`ProviderService` 直接读，agent 可通过工具自配置供应商。
